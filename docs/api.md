# REST API My Cloud

Документ фиксирует HTTP-контракт между Django и React. Базовый префикс закрытого API — `/api/v1/`.

## Общие правила

- API реализуется на Django REST Framework.
- Пути завершаются символом `/` в соответствии с настройкой Django.
- Идентификаторы записей передаются как целые положительные числа.
- Даты возвращаются в ISO 8601 с часовым поясом, например `2026-07-03T14:30:00+05:00`.
- Размеры файлов передаются целым числом байт.
- JSON используется для запросов и ответов с данными.
- Загрузка файла использует `multipart/form-data`.
- Скачивание возвращает поток байтов, поэтому не является JSON-ответом.
- Закрытые запросы используют session cookie Django.
- Все изменяющие запросы с сессией требуют корректный CSRF-токен.
- Закрытые маршруты проверяют роль и принадлежность объекта на сервере.
- Коллекции возвращаются в объекте с полем `items`, чтобы контракт можно было расширить пагинацией.

## Открытые и закрытые маршруты

Без действующей сессии доступны только:

- получение CSRF-токена;
- регистрация;
- вход;
- скачивание по публичной ссылке.

В исходном задании сказано защищать все вызовы кроме регистрации, но вход и получение CSRF-токена технически должны быть доступны до создания сессии, а публичное скачивание прямо предназначено внешнему посетителю. Это зафиксированные исключения.

## Единый формат ошибки

```json
{
  "error": {
    "code": "validation_error",
    "message": "Проверьте введённые данные.",
    "fields": {
      "username": ["Логин должен начинаться с латинской буквы."],
      "password": ["Пароль должен содержать специальный символ."]
    }
  }
}
```

Правила:

- `code` — стабильный машинный код в `snake_case`;
- `message` — понятное общее сообщение на русском языке;
- `fields` присутствует только для ошибок конкретных полей;
- необработанные исключения не раскрывают traceback, SQL, пути или настройки;
- CSRF-ошибки и ошибки Django также преобразуются в этот JSON-формат;
- запрос к чужому или несуществующему файловому объекту возвращает одинаковый безопасный `404`.

## Основные HTTP-статусы

| Статус | Назначение |
|---:|---|
| `200 OK` | Успешное чтение или изменение с телом ответа |
| `201 Created` | Пользователь или файл создан |
| `204 No Content` | Успешный выход или удаление без тела ответа |
| `400 Bad Request` | Некорректный JSON, multipart или параметры запроса |
| `401 Unauthorized` | Действующая сессия отсутствует |
| `403 Forbidden` | Сессия есть, но роли или CSRF-проверки недостаточно |
| `404 Not Found` | Ресурс не найден либо не должен быть раскрыт пользователю |
| `409 Conflict` | Конфликт уникальности или защита последнего администратора |
| `413 Content Too Large` | Файл превышает настроенный лимит |
| `415 Unsupported Media Type` | Неподдерживаемый формат тела запроса |
| `500 Internal Server Error` | Безопасно обработанная внутренняя ошибка |

## Представление пользователя

Обычный ответ о текущем пользователе:

```json
{
  "id": 17,
  "username": "alex24",
  "fullName": "Алексей Петров",
  "email": "alex@example.com",
  "isAdmin": false
}
```

В административном списке добавляется статистика:

```json
{
  "id": 17,
  "username": "alex24",
  "fullName": "Алексей Петров",
  "email": "alex@example.com",
  "isAdmin": false,
  "fileCount": 4,
  "storageSize": 2457600
}
```

Пароль, хеш, `storage_path`, технические флаги Django и внутренние даты в ответы не входят.

## Представление файла

```json
{
  "id": 42,
  "originalName": "report.pdf",
  "size": 245760,
  "comment": "Финальная версия",
  "uploadedAt": "2026-07-03T14:30:00+05:00",
  "lastDownloadedAt": null,
  "downloadUrl": "/api/v1/files/42/download/"
}
```

`relative_path`, `storage_name`, `public_token` и абсолютные пути никогда не возвращаются. Готовая публичная ссылка выдаётся только отдельным запросом владельца или администратора.

## Аутентификация

### Получить CSRF-токен

```http
GET /api/v1/auth/csrf/
```

Доступ: открытый.

Успешный ответ — `200 OK`:

```json
{
  "csrfToken": "token-value"
}
```

Ответ также устанавливает CSRF-cookie согласно настройкам окружения.

### Регистрация

```http
POST /api/v1/auth/register/
Content-Type: application/json
X-CSRFToken: <token>
```

Доступ: открытый.

```json
{
  "username": "alex24",
  "fullName": "Алексей Петров",
  "email": "alex@example.com",
  "password": "Strong#7"
}
```

Успешный ответ: `201 Created` с представлением пользователя. Регистрация не создаёт сессию автоматически: после неё пользователь переходит на страницу входа.

Ошибки:

- `400 validation_error` — поля не соответствуют требованиям;
- `409 username_already_exists` — логин занят;
- `409 email_already_exists` — email занят.

### Вход

```http
POST /api/v1/auth/login/
Content-Type: application/json
X-CSRFToken: <token>
```

Доступ: открытый.

```json
{
  "username": "alex24",
  "password": "Strong#7"
}
```

Успешный ответ: `200 OK` с представлением пользователя и session cookie.

Неверный логин и неверный пароль дают одинаковый ответ `401 invalid_credentials`, чтобы не раскрывать существование учётной записи.

### Текущий пользователь

```http
GET /api/v1/auth/me/
```

Доступ: пользователь или администратор.

Успешный ответ: `200 OK` с представлением текущего пользователя.

### Выход

```http
POST /api/v1/auth/logout/
X-CSRFToken: <token>
```

Доступ: пользователь или администратор.

Успешный ответ: `204 No Content`. Текущая сессия завершается.

## Управление пользователями

### Получить список пользователей

```http
GET /api/v1/users/
```

Доступ: только администратор.

Успешный ответ:

```json
{
  "items": [
    {
      "id": 17,
      "username": "alex24",
      "fullName": "Алексей Петров",
      "email": "alex@example.com",
      "isAdmin": false,
      "fileCount": 4,
      "storageSize": 2457600
    }
  ]
}
```

Порядок по умолчанию: дата регистрации от новых к старым. Статистика рассчитывается запросом к БД без чтения содержимого файлов на диске.

### Изменить прикладную роль

```http
PATCH /api/v1/users/{userId}/role/
Content-Type: application/json
X-CSRFToken: <token>
```

Доступ: только администратор.

```json
{
  "isAdmin": true
}
```

Успешный ответ: `200 OK` с административным представлением пользователя.

Ответ `409 last_admin_required` возвращается, если действие лишит систему последнего активного администратора.

### Удалить пользователя

```http
DELETE /api/v1/users/{userId}/
X-CSRFToken: <token>
```

Доступ: только администратор.

Успешный ответ: `204 No Content` после удаления пользователя и записей. Физическая очистка выполняется согласованным сервисом, описанным в `architecture.md`.

Удаление самого себя запрещается ответом `409 cannot_delete_current_user`. Последнего активного администратора удалить нельзя.

## Файловое хранилище

### Выбор хранилища

Обычный пользователь не передаёт владельца: сервер всегда использует текущую сессию.

Администратор может добавить параметр:

```text
?ownerId=17
```

Параметр поддерживается только списком и загрузкой файлов. Если администратор не передал `ownerId`, используется его собственное хранилище. Для операций над конкретным файлом владелец определяется по записи, а доступ проверяется сервером.

### Получить список файлов

```http
GET /api/v1/files/
GET /api/v1/files/?ownerId=17
```

Доступ: пользователь или администратор с учётом выбранного хранилища.

Успешный ответ:

```json
{
  "owner": {
    "id": 17,
    "username": "alex24"
  },
  "items": [
    {
      "id": 42,
      "originalName": "report.pdf",
      "size": 245760,
      "comment": "Финальная версия",
      "uploadedAt": "2026-07-03T14:30:00+05:00",
      "lastDownloadedAt": null,
      "downloadUrl": "/api/v1/files/42/download/"
    }
  ]
}
```

Порядок по умолчанию: дата загрузки от новых к старым.

### Загрузить файл

```http
POST /api/v1/files/
Content-Type: multipart/form-data
X-CSRFToken: <token>
```

Поля формы:

| Поле | Обязательное | Описание |
|---|---:|---|
| `file` | Да | Один загружаемый файл |
| `comment` | Нет | Комментарий, пустая строка по умолчанию |
| `ownerId` | Только для администратора | Владелец целевого хранилища |

Успешный ответ: `201 Created` с представлением файла.

Ошибки:

- `400 file_required` — файл отсутствует или имеет пустое имя;
- `403 storage_access_denied` — обычный пользователь передал чужого владельца;
- `413 file_too_large` — превышен лимит;
- `500 file_storage_error` — безопасно обработана ошибка записи.

### Изменить имя или комментарий

```http
PATCH /api/v1/files/{fileId}/
Content-Type: application/json
X-CSRFToken: <token>
```

Доступ: владелец или администратор.

Можно передать одно или оба поля:

```json
{
  "originalName": "new-report.pdf",
  "comment": "Исправленная версия"
}
```

Успешный ответ: `200 OK` с обновлённым представлением файла. Пустой объект возвращает `400 no_changes`.

### Удалить файл

```http
DELETE /api/v1/files/{fileId}/
X-CSRFToken: <token>
```

Доступ: владелец или администратор.

Успешный ответ: `204 No Content`.

### Авторизованное скачивание

```http
GET /api/v1/files/{fileId}/download/
```

Доступ: владелец или администратор.

Успешный ответ: `200 OK` с потоковым содержимым файла и безопасным `Content-Disposition` с оригинальным именем. После успешной подготовки ответа обновляется `lastDownloadedAt`.

### Получить публичную ссылку

```http
GET /api/v1/files/{fileId}/public-link/
```

Доступ: владелец или администратор.

Успешный ответ:

```json
{
  "publicUrl": "https://cloud.example/public/files/opaque-token/"
}
```

Запрос идемпотентен: для одного файла возвращается одна и та же ссылка, пока дополнительная функция перевыпуска токена не реализована.

## Публичное скачивание

```http
GET /public/files/{token}/
```

Доступ: открытый.

Успешный ответ: `200 OK` с потоковым содержимым и оригинальным именем в `Content-Disposition`. Дата последнего скачивания обновляется.

Неверный токен, удалённая запись и отсутствующий физический файл возвращают одинаковый безопасный `404 Not Found`. Для публичного маршрута допустим стандартный ответ страницы ошибки без внутренних деталей; запрос из SPA к этому маршруту не требуется.

## Коды ошибок

| Код | HTTP | Смысл |
|---|---:|---|
| `validation_error` | 400 | Одно или несколько полей не прошли проверку |
| `bad_request` | 400 | Тело или параметры запроса невозможно обработать |
| `no_changes` | 400 | PATCH не содержит поддерживаемых полей |
| `invalid_credentials` | 401 | Неверные данные входа |
| `authentication_required` | 401 | Требуется действующая сессия |
| `csrf_failed` | 403 | CSRF-токен отсутствует или неверен |
| `permission_denied` | 403 | Роль не позволяет выполнить действие |
| `storage_access_denied` | 403 | Нет доступа к выбранному хранилищу |
| `not_found` | 404 | Ресурс не найден или скрыт правилами доступа |
| `username_already_exists` | 409 | Логин уже зарегистрирован |
| `email_already_exists` | 409 | Email уже зарегистрирован |
| `last_admin_required` | 409 | Нельзя убрать последнего активного администратора |
| `cannot_delete_current_user` | 409 | Администратор не может удалить текущую учётную запись |
| `file_too_large` | 413 | Файл превышает лимит |
| `unsupported_media_type` | 415 | Формат тела запроса не поддерживается |
| `file_storage_error` | 500 | Ошибка физического хранения без раскрытия пути |
| `internal_error` | 500 | Непредвиденная внутренняя ошибка |

## Журналирование API

Для каждого запроса фиксируются метод, шаблон маршрута, HTTP-статус, длительность и идентификатор пользователя при наличии. Дополнительно журналируются:

- успешная и отклонённая регистрация без введённых значений пароля;
- вход и выход без session cookie;
- административные изменения;
- загрузка, изменение, скачивание и удаление по идентификатору записи;
- публичное скачивание без полного токена;
- ошибки файловой системы без абсолютного пути в пользовательском ответе.

Email, пароль, cookie, CSRF-токен, публичный токен и содержимое файла в журнал не попадают.
