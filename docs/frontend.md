# Frontend-архитектура My Cloud

Документ описывает маршруты, экраны, состояние и основные компоненты SPA. Источником данных служит REST API из `api.md`.

## Технологии

- React с функциональными компонентами и хуками;
- React Router для клиентских маршрутов;
- Redux Toolkit для общего серверного состояния;
- Vite для разработки и production-сборки;
- Yarn Classic 1.22.22 для зависимостей и команд;
- Vitest, Testing Library и user-event для тестов;
- обычный CSS с понятной системой классов без обязательной библиотеки компонентов.

Формы хранят временные значения локально в компонентах. Redux используется для сессии, пользователей, файлов и состояний асинхронных запросов, которые нужны нескольким экранам.

## Маршруты SPA

| Путь | Экран | Доступ | Назначение |
|---|---|---|---|
| `/` | `HomePage` | Все | Описание приложения и основные действия |
| `/register` | `RegisterPage` | Только гость | Регистрация пользователя |
| `/login` | `LoginPage` | Только гость | Вход в приложение |
| `/storage` | `StoragePage` | Пользователь и администратор | Собственное файловое хранилище |
| `/admin/users` | `UsersPage` | Только администратор | Пользователи и статистика хранилищ |
| `/admin/users/:userId/files` | `StoragePage` | Только администратор | Хранилище выбранного пользователя |
| `*` | `NotFoundPage` | Все | Страница 404 и переход на доступную главную страницу |

Прямое открытие любого маршрута должно возвращать оболочку SPA с сервера. React Router после загрузки выбирает нужный экран.

## Переход после входа

- обычный пользователь переходит на `/storage`;
- администратор переходит на `/admin/users`;
- если пользователь был перенаправлен на вход с закрытого маршрута, после успешного входа можно вернуть его на исходный разрешённый маршрут;
- гость, открывший закрытый маршрут, перенаправляется на `/login`;
- обычный пользователь, открывший административный маршрут, перенаправляется на `/storage` с понятным уведомлением;
- аутентифицированный пользователь, открывший `/login` или `/register`, перенаправляется на стартовый экран своей роли.

## Инициализация приложения

1. При запуске отображается нейтральный экран загрузки оболочки.
2. Приложение запрашивает `/api/v1/auth/me/` с `credentials: include`.
3. При `200` Redux сохраняет пользователя и роль.
4. При `401` устанавливается состояние гостя без сообщения об ошибке.
5. Только после завершения проверки сессии выполняются защищённые переходы.

Такой порядок предотвращает краткое отображение гостевых или административных элементов до восстановления сессии.

## Навигация

Общий компонент `AppHeader` присутствует на всех экранах.

Гость видит:

- «Главная»;
- «Вход»;
- «Регистрация».

Обычный пользователь видит:

- «Главная»;
- «Мои файлы»;
- «Выход».

Администратор видит:

- «Главная»;
- «Мои файлы»;
- «Пользователи»;
- «Выход».

Навигация реализуется через `NavLink`. Активный пункт имеет визуальное отличие и `aria-current="page"`. Выход выполняется кнопкой, потому что изменяет состояние сессии.

## Экраны

### Главная страница

Содержит:

- название My Cloud;
- краткое описание возможностей;
- для гостя — кнопки регистрации и входа;
- для пользователя — переход к своим файлам;
- для администратора — переход к пользователям и своим файлам.

Главная страница не загружает списки пользователей или файлов.

### Регистрация

Поля:

- логин;
- полное имя;
- email;
- пароль;
- подтверждение пароля только на клиенте.

Клиент повторяет основные правила сервера для быстрой обратной связи, но ответ backend остаётся окончательным. Ошибки показываются рядом с полями и в общей области с `role="alert"` при необходимости.

После успешной регистрации отображается подтверждение и выполняется переход на `/login`. Пароль очищается при любом завершённом запросе и не сохраняется в Redux, storage браузера или журнале.

### Вход

Поля:

- логин;
- пароль.

Во время запроса кнопка блокируется и показывает состояние выполнения. При неверных данных отображается общее сообщение без уточнения, существует ли логин. После успеха выполняется переход по роли.

### Список пользователей

Административная таблица содержит:

- логин;
- полное имя;
- email;
- признак администратора;
- количество файлов;
- общий размер файлов;
- переход к хранилищу;
- действия изменения роли и удаления.

Изменение роли и удаление требуют подтверждения. Интерфейс заранее блокирует очевидно опасные действия над текущим или последним администратором, но сервер в любом случае повторно проверяет ограничения.

На узком экране строки превращаются в карточки с подписями полей.

### Файловое хранилище

В верхней части отображаются:

- заголовок «Мои файлы» либо имя выбранного пользователя для администратора;
- возврат к списку пользователей при просмотре чужого хранилища;
- форма загрузки файла и комментария.

Список файлов содержит:

- оригинальное имя;
- комментарий;
- размер в удобном формате;
- дату загрузки;
- дату последнего скачивания или «Ещё не скачивался»;
- действия скачивания, переименования, изменения комментария, копирования публичной ссылки и удаления.

Переименование и комментарий редактируются в форме или диалоге с явными действиями «Сохранить» и «Отмена». Удаление требует подтверждения. После успешного действия Redux обновляет соответствующую запись без полной перезагрузки страницы.

## Состояния экрана

Каждый экран с серверными данными различает:

- первоначальную загрузку;
- успешную загрузку с данными;
- успешную загрузку пустого списка;
- ошибку с возможностью повторить запрос;
- фоновое обновление;
- выполнение конкретного действия.

Блокировка одной строки не должна блокировать действия с остальными файлами или пользователями. Идентификатор выполняемой операции хранится отдельно от общего статуса списка.

## Redux-состояние

### `authSlice`

```text
user: User | null
status: idle | loading | authenticated | anonymous | failed
error: ApiError | null
```

Действия:

- получить текущую сессию;
- зарегистрировать пользователя;
- войти;
- выйти;
- очистить ошибку формы.

Пароли и CSRF-токен в Redux не сохраняются.

### `usersSlice`

```text
items: AdminUser[]
status: idle | loading | succeeded | failed
error: ApiError | null
roleUpdatingId: number | null
deletingId: number | null
```

Действия:

- получить список;
- изменить роль;
- удалить пользователя;
- очистить состояние при выходе.

### `filesSlice`

```text
owner: StorageOwner | null
items: StoredFile[]
status: idle | loading | succeeded | failed
error: ApiError | null
uploadStatus: idle | loading | succeeded | failed
updatingId: number | null
deletingId: number | null
sharingId: number | null
```

Действия:

- получить файлы выбранного хранилища;
- загрузить файл;
- изменить имя или комментарий;
- удалить файл;
- получить публичную ссылку;
- очистить состояние при смене владельца или выходе.

Публичный URL после копирования не требуется постоянно хранить в общем состоянии.

### Локальное состояние

В компонентах остаются:

- значения полей форм;
- видимость диалогов;
- выбранный файл перед отправкой;
- временное сообщение «Ссылка скопирована»;
- клиентские ошибки до отправки.

## API-клиент

Единый модуль `apiClient`:

- добавляет префикс `/api/v1`;
- всегда использует `credentials: 'include'`;
- для изменяющих запросов читает CSRF-cookie и добавляет `X-CSRFToken`;
- не задаёт `Content-Type` вручную для `FormData`;
- разбирает единый формат JSON-ошибки;
- корректно обрабатывает ответы `204 No Content`;
- при неожиданном не-JSON ответе формирует безопасную общую ошибку;
- не выполняет автоматический повтор изменяющих запросов;
- при `401` закрытого запроса сбрасывает сессию и направляет пользователя на вход.

Скачивание выполняется обычным переходом или отдельной функцией, которая получает blob и сохраняет имя из `Content-Disposition`. Выбор фиксируется при реализации после проверки поведения браузеров.

```text

├── app/
│   ├── store.js

│   └── apiClient.js
├── components/
│   ├── AppHeader.jsx

│   └── ProtectedRoute.jsx
├── features/
│   ├── auth/
│   ├── files/
│   └── users/
├── pages/
│   ├── HomePage.jsx
│   ├── LoginPage.jsx
```

Компоненты дробятся по ответственности по мере роста. Небольшие компоненты не выносятся в отдельный файл только ради количества файлов.

## Доступность

- Для структуры используются `header`, `nav`, `main`, `section`, `form`, `table` и другие подходящие элементы.
- У каждого поля есть связанный `label`.
- Ошибки доступны через `role="alert"` или `aria-describedby`.
- Диалоги получают заголовок, корректный фокус и закрытие клавишей Escape.
- После асинхронного успеха или ошибки важное сообщение объявляется через `aria-live`.
- Иконки действий имеют текстовое доступное имя и `title` как дополнительную подсказку.
- Все операции доступны с клавиатуры.
- Фокус заметен и не удаляется стилями.
- Цвет не является единственным способом показать состояние.
- Макет работает от ширины 320 px.
- Движение отключается или сокращается при `prefers-reduced-motion: reduce`.

## Обработка дат и размеров

- API передаёт даты в ISO 8601, форматирование выполняется через `Intl.DateTimeFormat('ru-RU')`.
- Пустая дата последнего скачивания отображается текстом, а не некорректной датой.
- Размер форматируется чистой функцией в байты, КБ, МБ или ГБ.
- Чистые функции форматирования размещаются отдельно и покрываются unit-тестами.

## Тестирование

Vitest использует `jsdom`, Testing Library и user-event. Порог покрытия собственного тестируемого frontend-кода — 100% по statements, branches, functions и lines.

Обязательные проверки:

- восстановление действующей и отсутствующей сессии;
- гостевая и ролевая навигация;
- защищённые и административные маршруты;
- прямое открытие каждого маршрута и страница 404;
- клиентская и серверная валидация регистрации;
- успешный и неуспешный вход;
- выход и очистка общего состояния;
- загрузка, переименование, комментарий, скачивание, публичная ссылка и удаление;
- административный список, смена роли и удаление пользователя;
- загрузка, пустой список, ошибка и повтор запроса;
- доступные имена элементов и управление с клавиатуры;
- чистые функции форматирования;
- обработка `204`, JSON-ошибок и неожиданного ответа API.

Тесты проверяют наблюдаемое поведение через роли и доступные имена, а не внутреннюю структуру компонентов.

## Production-сборка

- Vite создаёт статические файлы в `frontend/dist`.
- Django собирает или копирует артефакты в настроенный каталог статики при развёртывании.
- Fallback-маршрут Django возвращает `index.html` только для путей SPA, но не маскирует `/api/`, `/public/` и статические файлы.
- Команда `yarn validate` выполняет `yarn lint`, `yarn test:coverage` и `yarn build`.
- Сборка не содержит source map в production, если их безопасное размещение отдельно не настроено.
